## 3. How We Use Your Data

We use your data exclusively for:

1. **Jira Integration** — Reading and writing Jira issues, projects, and comments on your behalf
2. **Wrike Integration** — Reading and writing Wrike tasks, folders, and comments on your behalf
3. **Session Management** — Maintaining your authenticated session
4. **AI Task Breakdown** (optional) — Generating work breakdowns from your requirement descriptions
5. **Security & Auditing** — Logging connection events and token refreshes for security monitoring
6. **Real-time Updates** — Synchronizing the UI when Jira issues change via webhooks

We do **not** use your data for:

- Advertising or marketing profiling
- Selling to third parties
- Training AI models (OpenAI API data is not used for training by default)
- Analytics or behavioral tracking

## 5. Data Storage & Security

### 5.1 Encryption at Rest

- **Jira OAuth tokens** are encrypted using **AES-256-GCM** at the application layer before storage in the database. Plaintext tokens never exist in the database.
- **Wrike OAuth tokens** use the same **AES-256-GCM** application-layer encryption before database storage.
- **Database storage** is encrypted at rest using **AES-256** (Azure-managed encryption on Azure Database for PostgreSQL).
- **Backups** are encrypted at rest using the same AWS-managed encryption.

For full technical details, see the [Encryption at Rest](./encryption-at-rest.md) document.

### 5.2 Encryption in Transit

- All browser-to-server communication uses **HTTPS (TLS 1.2+)**
- All server-to-database connections use **TLS** (`sslmode=require`)
- All server-to-Jira API connections use **HTTPS**
- All server-to-Wrike API connections use **HTTPS**
- Session cookies are set with `secure: true` (HTTPS-only), `httpOnly: true` (no JavaScript access), and `sameSite: "none"`

### 5.3 Access Controls

- `DATABASE_URL` is stored as an environment variable and is never exposed to the browser
- OAuth tokens are encrypted at the application layer before insert
- Database access is via Azure PostgreSQL logins, not a public anon key
- Session tokens are 256-bit cryptographically random values

## 7. Your Rights & How to Exercise Them

If you are in the European Economic Area (EEA), United Kingdom, or other jurisdictions with data protection laws, you have the following rights:

| Right                | How to Exercise                                                                                                                                                                                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Erasure**          | Click **Disconnect** in the App UI to deactivate your connection and delete your session. Jira users can also revoke access via [Atlassian Connected Apps](https://id.atlassian.com/manage-profile/apps). Wrike users can revoke the app via Wrike **Apps & Integrations** or disconnect with `wipe: true` to remove setup data. |
| **Withdraw Consent** | Stop using the AI feature at any time — no AI data is persisted. Disconnect to revoke all platform access consent.                                                                                                                                                                                                               |

**Note:** The App does not collect email addresses, names, or other contact information. It only stores platform pseudonymous identifiers (Jira `accountId` or Wrike contact ID). Data subject requests should be routed through the Sitecore Marketplace support channel or your organization's platform administrator.

For the technical procedures used to fulfill data subject requests, see the [DSAR Workflow](./dsar-workflow.md) document.
